## 二、学员如何注册

登录页切到「注册」，只需填：**用户名**（3–16 位字母/数字/下划线）+ **昵称**（选填）+ **密码**（≥6 位，两次一致）。
无需邮箱、手机号、验证码；注册成功即自动登录。管理员也可以在「数据观测台 → 账号管理 → 新增账号」里批量建号（适合班级演练统一发号）。

## 三、管理员控制台能做什么（首页 → 数据观测台）

1. **训练数据看板**：6 个 KPI（注册账号 / 完成训练 / 平均后测识别率 / 今日活跃 / 平均综合分 / 题库题量）。
2. **训练成效分析图**：前测→后测识别率折线图（按学员排序，含群体均值参考线与平均提升）。
3. **破绽漏判结构图**：7 类破绽漏判占比环形图（含次数与百分比图例）。
4. **题库编辑**：按内置题目同一套 Schema 追加自定义题目，**保存后立即生效**，新题会自动进入「每日挑战」；编入波次后也会出现在拦截战里。
   - 点「插入模板」会给你一道带 `data-el` 靶点写法的示例题，照着改即可；
   - 「校验 JSON」会逐条检查 id 重复、carrier/难度合法性、破绽类别是否 7 类之一、`redflags.target` 是否能对应到靶点，并给出中文错误定位；
   - 字段名以 `_` 开头视为注释，保存时自动丢弃。
5. **波次编排**：改 4 波题序（第 1 波=前测、第 4 波=后测，报告页的前后测识别率取这两波；`reveal: true` 的波次分拣完进拆解台）。保存后下一局拦截战即按新波次出题。
6. **账号管理**：账号列表（角色/注册时间/训练状态）· 新增账号 · 重置密码（一次性显示新密码）· 删除账号（连带清掉该账号训练数据，不能删自己或最后一个管理员）。
7. **数据导出**：全量 JSON（账号+题库+波次+全部训练存档，用于换机迁移/备份）与成绩 CSV（Excel 直接打开，含前测/后测/提升/段位/战绩/错题数）。

## 四、数据存在哪、怎么迁移

| 内容 | localStorage 键 | 作用域 |
|---|---|---|
| 账号表（含 salt+哈希） | `shiyu_users` | 本机共享 |
| 登录会话 | `shiyu_session` | 本机共享 |
| 学员训练存档 | `shiyu_v3@用户名` | 按账号隔离 |
| 错题本 | `shiyu_wrong@用户名` | 按账号隔离 |
| 每日挑战记录 | `shiyu_daily@用户名` | 按账号隔离 |
| AI 诊断缓存 | `shiyu_ai_diag@用户名` | 按账号隔离 |
| 自定义题库 | `shiyu_bank` | 全站共享（管理员维护） |
| 管理员波次 | `shiyu_waves` | 全站共享（管理员维护） |

- 所有数据**只在本机浏览器**，换电脑 / 换浏览器 / 清缓存即丢失 —— 迁移请用「数据导出 JSON」+「覆盖导入」。
- 管理员改题库/波次只影响**当前浏览器**；要让全班同学都用上新题，需在各台机器分别导入题库 JSON，或等后端化（开发文档 §7）后改为服务端存储。

## 五、安全与合规（重要）

- 密码**不存明文**：每个账号独立随机 salt，存 `SHA-256(salt:密码:salt)`。因局域网 `http://` 下浏览器不提供 `crypto.subtle`，项目内置了一份纯 JS SHA-256（已与 Node 原生实现逐串比对一致）。
- 这仍是**演示级本机鉴权**：账号表在本机浏览器里，清缓存即失效、也不防同机改动。正式对外部署必须换成服务端鉴权（账号表落库、密码加盐哈希、会话用 Token），见 `识渔计划_开发文档.md` §7 后端化路线。
- 合规口径已同步进「关于本作品」页：账号仅存本机、不上传、不收集个人信息。
- **交付前请执行**：逐个登录 `admin01`–`admin05`，用「账号管理 → 重置密码」改掉初始密码，并删除/归档本文件。
